# 提案：云服务器部署 + GitHub Actions 自动化

## 为什么

当前项目（AetherViz 小学教学）仅在本地开发环境运行，无法对外提供服务。为了将应用发布到外网，需要一个稳定、可控、成本合理的部署方案。

同时，用户有多个独立项目（个人主页、摄影作品、小工具集合），需要一个能够承载多个项目、支持独立部署、互不影响的基础架构。

**为什么选择云主机 + GitHub Actions：**
- ✅ **完全控制**：不受平台限制，可安装任何需要的服务
- ✅ **成本可控**：流量越大越划算，适合长期运营
- ✅ **多项目友好**：一台主机可部署多个项目，共享基础设施
- ✅ **自动化部署**：Git Push 后自动构建部署，无需手动操作
- ✅ **灵活扩展**：未来可轻松添加后端服务（数据库、API 等）

## 变更内容

### 新增部署架构

**阶段 A：云服务器基础设施（一次性配置）**
- 购买阿里云/腾讯云 ECS（2核4GB，Ubuntu 22.04）
- 配置域名解析（子域名映射到 ECS IP）
- 配置安全组（开放 22/80/443 端口）
- 安装基础环境（Nginx、Node.js、Git）
- 配置 Nginx 多站点支持
- 申请并配置 SSL 证书（Let's Encrypt + Certbot）

**阶段 B：自动化部署系统（配置一次，永久使用）**
- 生成 SSH 密钥对（免密登录）
- 配置 GitHub Secrets（SSH 密钥、服务器信息）
- 创建 GitHub Actions 工作流（自动构建 + 部署）
- 配置部署后自动化脚本（重启 Nginx、清理缓存）

### 新增部署能力

- **CI/CD 流水线**：代码推送后自动构建、测试、部署
- **多项目支持**：支持独立部署多个项目到同一服务器
- **零停机部署**：使用软切换机制，用户无感知更新
- **回滚能力**：保留历史版本，可快速回滚
- **SSL 自动续期**：证书自动更新，无需手动干预

### 项目结构变更

**当前**：单一代码仓库，仅支持本地开发

**变更后**：多项目架构
```
your-projects/
├── math-education/          # 当前项目（独立仓库）
│   ├── .github/workflows/deploy.yml
│   └── 自动部署到 /var/www/math-education
│
├── photography/             # 摄影作品（独立仓库，未来）
│   ├── .github/workflows/deploy.yml
│   └── 自动部署到 /var/www/photography
│
└── personal-site/           # 个人主页（独立仓库，未来）
    ├── .github/workflows/deploy.yml
    └── 自动部署到 /var/www/personal-site
```

## 功能 (Capabilities)

### 新增功能

- `cloud-server-infrastructure`: 云服务器基础设施
  - ECS 购买和初始化
  - 基础环境安装（Nginx、Node.js、Git）
  - 安全组配置
  - 防火墙设置

- `ssl-certificates`: SSL 证书管理
  - Let's Encrypt 证书申请
  - Certbot 自动配置
  - 证书自动续期
  - 多域名 SSL 支持

- `nginx-multi-site`: Nginx 多站点配置
  - 虚拟主机配置
  - 反向代理设置
  - 静态资源缓存
  - Gzip 压缩

- `automated-deployment`: 自动化部署系统
  - GitHub Actions 工作流
  - SSH 密钥管理
  - 自动构建和部署
  - 部署后脚本执行

- `multi-project-management`: 多项目管理
  - 独立项目隔离
  - 共享基础设施
  - 统一监控日志
  - 备份策略

## 影响

### 基础设施

**新增依赖：**
- 阿里云/腾讯云 ECS 服务器
- 域名及 DNS 解析
- GitHub Secrets 管理

**成本影响：**
- ECS：约 ¥60/月（2核4GB）
- 带宽：按量付费，预估 ¥10-30/月
- 域名：已有，无额外成本
- **月度总成本：约 ¥70-90**

### 开发流程

**变更前：**
```
本地开发 → 本地测试 → 无法对外访问
```

**变更后：**
```
本地开发 → Git Push → GitHub Actions 自动构建部署 → 用户访问
```

### 运维负担

**新增运维职责：**
- 服务器安全更新（每月一次，10分钟）
- 日志监控（按需）
- 备份策略（自动化，可配置）
- SSL 证书续期（自动化）

**时间成本：**
- 初始配置：2-3 小时（一次性）
- 日常维护：几乎为零（自动化）

### 安全考虑

**新增安全措施：**
- SSH 密钥认证（禁用密码登录）
- 防火墙规则（仅开放必要端口）
- Fail2ban（防暴力破解）
- 定期安全更新

**风险缓解：**
- 数据备份：定期备份到云存储
- 监控告警：配置服务器资源监控
- 灾难恢复：保留快照，可快速恢复

### 用户体验

**改进：**
- ✅ 项目可从外网访问
- ✅ 访问速度快（国内 CDN）
- ✅ SSL 加密（安全可信）
- ✅ 稳定可靠（99.9% 可用性）

**无负面影响：**
- 本地开发流程不变
- 代码无需修改（仅新增部署配置）
