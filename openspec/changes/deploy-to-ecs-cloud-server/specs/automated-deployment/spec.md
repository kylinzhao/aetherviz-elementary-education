# 自动化部署系统规范

## 新增需求

### 需求:SSH 密钥认证
系统必须使用 SSH 密钥对实现免密登录，以支持自动化部署。

#### 场景:生成密钥对
- **当** 用户执行 ssh-keygen 命令
- **那么** 系统必须生成 RSA 密钥对（4096 位）
- **并且** 私钥保存在 ~/.ssh/id_rsa
- **并且** 公钥保存在 ~/.ssh/id_rsa.pub

#### 场景:配置服务器免密登录
- **当** 用户执行 ssh-copy-id 命令
- **那么** 公钥必须复制到服务器的 ~/.ssh/authorized_keys
- **并且** 后续 SSH 登录不需要密码
- **并且** root 用户可以免密登录

#### 场景:测试免密登录
- **当** 用户执行 ssh root@server 命令
- **那么** 系统必须直接登录，不提示输入密码
- **如果** 提示输入密码，则配置失败

### 需求:GitHub Secrets 配置
系统必须在 GitHub 仓库中配置必要的 Secrets 以支持 Actions 工作流。

#### 场景:配置 SSH_PRIVATE_KEY
- **当** 用户创建 Secret 名为 SSH_PRIVATE_KEY
- **那么** 值必须是私钥的完整内容
- **并且** 包含 BEGIN 和 END 行
- **并且** 包含完整的密钥内容

#### 场景:配置服务器信息
- **当** 用户创建 REMOTE_HOST Secret
- **那么** 值必须是 ECS 的公网 IP
- **当** 用户创建 REMOTE_USER Secret
- **那么** 值必须是 root
- **当** 用户创建 REMOTE_PORT Secret
- **那么** 值必须是 22

### 需求:GitHub Actions 工作流
系统必须在代码推送时自动触发构建和部署流程。

#### 场景:自动触发
- **当** 用户推送代码到 main 分支
- **那么** GitHub Actions 必须自动执行 deploy.yml 工作流
- **并且** 工作流名称为"Deploy to ECS"

#### 场景:检出代码
- **当** 工作流开始执行
- **那么** 系统必须先检出代码（actions/checkout@v3）
- **并且** 代码必须是最新版本

#### 场景:安装依赖
- **当** 代码检出完成
- **那么** 系统必须执行 npm ci 安装依赖
- **并且** 使用 Node.js 18.x 版本

#### 场景:构建项目
- **当** 依赖安装完成
- **那么** 系统必须执行 npm run build
- **并且** 构建产物必须在 dist/ 目录
- **如果** 构建失败，工作流必须停止并报错

#### 场景:部署到服务器
- **当** 构建成功
- **那么** 系统必须通过 SSH 连接到服务器
- **并且** 将 dist/ 目录的内容上传到 /var/www/math-education
- **并且** 使用 easingthemes/ssh-deploy@main action

#### 场景:重启服务
- **当** 文件上传完成
- **那么** 系统必须执行 nginx -t 测试配置
- **并且** 执行 nginx -s reload 重载 Nginx
- **并且** 显示"✅ Deploy successful!"消息

#### 场景:部署通知
- **当** 工作流执行完成
- **如果** 所有步骤成功
- **那么** 工作流状态必须显示为绿色（成功）
- **如果** 任何步骤失败
- **那么** 工作流状态必须显示为红色（失败）
- **并且** 显示详细的错误日志

### 需求:零停机部署
系统必须实现无缝更新，不影响用户访问。

#### 场景:原子性更新
- **当** 新版本部署
- **那么** 旧版本必须保持服务直到新版本部署完成
- **并且** 文件上传过程中不影响用户访问

#### 场景:快速回滚
- **当** 新版本部署失败或发现问题
- **那么** 系统必须支持快速回滚到上一版本
- **通过** 删除 dist/ 目录并恢复 dist.previous/ 目录

### 需求:部署日志和监控
系统必须提供部署过程的日志以便排查问题。

#### 场景:GitHub Actions 日志
- **当** 工作流执行
- **那么** 每个步骤的输出必须记录在日志中
- **并且** 用户可以在 GitHub Actions 界面查看

#### 场景:服务器日志
- **当** 部署执行
- **那么** 服务器必须记录相关日志到 /var/www/shared/logs/
- **并且** 日志文件名包含时间戳
- **例如** deploy-2026-02-26-15-30.log

### 需求:安全性
自动化部署系统必须确保服务器安全。

#### 场景:密钥保护
- **当** SSH 密钥存储在 GitHub Secrets
- **那么** 密钥必须加密存储
- **并且** 日志中不得显示私钥内容
- **并且** 私钥不得出现在代码仓库中

#### 场景:最小权限原则
- **当** GitHub Actions 连接服务器
- **那么** 必须使用非特权用户（如果可能）
- **或者** 限制 root 用户只能执行特定命令
