# 扩展小学教学内容 - 技术设计文档

## 上下文

### 当前状态
AetherViz应用已完成12个教学页面，建立了成熟的技术架构：
- Three.js r134用于3D可视化
- Tailwind CSS用于样式
- 模块化JavaScript系统（问答、任务、无障碍）
- 响应式设计（移动/平板/桌面）
- WCAG 2.1 AA无障碍合规

### 约束条件
- 必须保持与现有页面的设计一致性
- 单HTML文件架构（便于部署和使用）
- 不引入新的外部依赖
- 支持离线使用（CDN依赖除外）
- 代码复用和可维护性

### 利益相关者
- 小学生（1-6年级）：最终用户
- 教师：教学辅助工具使用者
- 开发团队：维护和扩展

## 目标 / 非目标

**目标：**
1. 快速创建27个高质量教学页面，覆盖小学核心知识点
2. 保持现有代码质量和用户体验标准
3. 确保所有新页面通过无障碍测试
4. 最大化代码复用，减少开发时间
5. 提供多样化的3D可视化效果

**非目标：**
- 不修改现有页面的功能
- 不引入新的技术栈或框架
- 不实现后端服务或数据库
- 不创建复杂的用户账户系统

## 决策

### 决策1：批量创建策略

**选择**：分三批创建27个页面（高优先级8个 + 中优先级10个 + 低优先级9个）

**理由**：
- 降低单次工作量，便于质量把控
- 优先完成核心知识点（对称、角度、乘法、面积、立体几何）
- 后续批次可以基于前期经验优化

**替代方案**：
- 一次性创建所有27个页面 ❌ 工作量过大，质量难以保证
- 按学科创建（所有数学然后所有科学）❌ 会错过跨学科的代码复用机会

### 决策2：代码复用策略

**选择**：创建模板系统和组件库

**实现**：
```
templates/
├── components/          # 新增：可复用组件
│   ├── 3d-scene.js     # Three.js场景初始化模板
│   ├── controls.js     # 标准控制面板组件
│   ├── animations.js   # 常用动画效果库
│   └── static-diagram.js # SVG静态图生成器
└── lesson-*.html       # 27个教学页面
```

**理由**：
- 减少重复代码约60%
- 统一交互模式和视觉风格
- 便于后续维护和更新

**替代方案**：
- 每个页面独立编写 ❌ 大量重复代码，维护困难
- 使用框架（React/Vue）❌ 引入复杂性，违背单文件架构原则

### 决策3：3D可视化实现方式

**选择**：根据知识点特点选择最适合的3D表现方式

**分类实现**：
- **几何图形**：Three.js几何体 + 材质变化
- **动态过程**（水循环、声音传播）：粒子系统 + 路径动画
- **结构展示**（长方体、圆柱）：展开动画 + 透明度控制
- **交互模拟**（电路、磁铁）：点击交互 + 状态机

**理由**：
- 不同知识点需要不同的可视化策略
- 统一的Three.js底层但多样化的表现层
- 充分利用现有12个页面的实现经验

### 决策4：静态教学图生成

**选择**：使用SVG生成简洁的教育示意图

**实现**：
- 创建SVG模板库
- 每个页面1-3个静态图
- 支持中英文标注
- 高对比度配色

**理由**：
- SVG轻量且可缩放
- 适合打印和屏幕阅读器
- 与3D动画形成互补

### 决策5：问答和任务系统集成

**选择**：第一批页面不集成问答/任务系统，后续批次选择性集成

**理由**：
- 先完成核心3D可视化功能
- 问答和任务需要大量内容创作时间
- 可以在后续变更中逐步添加

**替代方案**：
- 所有页面都集成问答/任务 ❌ 内容工作量过大
- 完全不集成 ❌ 浪费已有的系统模块

### 决策6：性能优化策略

**选择**：按需加载和优化策略

**实现**：
- 首页只显示课程卡片，不预加载3D场景
- 使用轻量级几何体（低多边形）
- 动画帧率限制在30-60fps
- 懒加载高清纹理

**理由**：
- 27个页面会显著增加应用体积
- 移动设备性能有限
- 保持流畅的用户体验

## 风险 / 权衡

### 风险1：开发周期长
**风险**：27个页面可能需要数周时间完成
**缓解措施**：
- 分批交付，每批8-10个页面
- 优先完成高优先级页面
- 使用代码模板加速开发

### 风险2：代码质量一致性
**风险**：批量创建可能导致质量参差不齐
**缓解措施**：
- 建立代码审查清单
- 使用统一模板和组件
- 每批完成后进行测试

### 风险3：3D场景复杂性
**风险**：某些知识点（如水循环、电路）难以用3D表现
**缓解措施**：
- 提前进行技术可行性验证
- 使用2D+3D混合方案
- 参考现有教育软件的可视化方式

### 风险4：浏览器兼容性
**风险**：Three.js在低端设备上性能问题
**缓解措施**：
- 提供性能降级选项（降低细节级别）
- 添加设备检测和建议
- 优化几何体和材质

### 风险5：内容准确性
**风险**：科学概念的3D可视化可能存在误导
**缓解措施**：
- 参考小学教材和课程标准
- 使用简化的教育模型而非完全精确的物理模拟
- 添加文字说明指出简化之处

## 技术规格

### 页面结构模板
```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>[页面名称] - AetherViz 小学教学</title>
    <script src="https://cdn.tailwindcss.com"></script>
    <script src="https://cdnjs.cloudflare.com/ajax/libs/three.js/r134/three.min.js"></script>
    <script src="../modules/accessibility.js"></script>
    <!-- 可选：问答和任务系统 -->
</head>
<body>
    <!-- 3D场景容器 -->
    <div id="scene-container"></div>

    <!-- 控制面板 -->
    <div id="controls">
        <!-- 参数控制滑块/按钮 -->
    </div>

    <!-- 静态展示容器 -->
    <div id="static-container" class="hidden">
        <!-- SVG教学图 -->
    </div>

    <!-- 脚本 -->
    <script>
        // Three.js场景初始化
        // 交互控制
        // 动画循环
    </script>
</body>
</html>
```

### 性能指标
- 首次加载时间：< 3秒
- 3D场景FPS：30-60fps
- 内存占用：< 200MB per页面
- 移动设备兼容性：iOS 12+, Android 8+

### 质量标准
- 通过Lighthouse性能测试（>90分）
- 通过WCAG 2.1 AA无障碍测试
- 通过axe DevTools无障碍测试
- 手动测试：所有交互功能正常
