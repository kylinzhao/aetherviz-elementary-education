# AetherViz 小学教学应用技术设计

## 上下文

AetherViz Master 是一个基于 AI 的互动教育可视化工具，能够将抽象教学概念转化为 3D 交互式网页。当前系统主要面向高中和大学水平的教学，界面和交互复杂度较高。

本设计旨在将 AetherViz Master 扩展到小学教育领域（1-6 年级），通过以下方式适配小学生的认知特点：

1. **简化界面交互**：减少复杂参数，增大操作控件
2. **视觉友好设计**：卡通化图标、明亮配色、动画效果
3. **语音辅助功能**：帮助不识字或阅读困难的学生
4. **游戏化学习**：通过问答、任务、成就激励持续学习

**当前状态**：
- AetherViz Master v5.0 已支持 Three.js + SVG 混合渲染
- 现有配色方案和技术栈可直接复用
- 生成的 HTML 文件支持离线使用

**约束条件**：
- 必须保持单文件 HTML 输出（零依赖）
- 必须在浏览器中直接运行，无需后端服务
- 必须支持桌面和移动设备
- 文字大小和交互必须符合小学生认知能力

**利益相关者**：
- 小学生（1-6 年级）：主要用户
- 教师：课堂演示工具
- 家长：家庭学习辅助

---

## 目标 / 非目标

**目标：**

1. 创建适配小学生认知水平的 3D 可视化教学模块（数学、科学）
2. 实现儿童友好的交互界面（大控件、语音提示、卡通风格）
3. 提供游戏化学习功能（问答、任务、成就、进度追踪）
4. 保持零依赖单文件 HTML 输出格式
5. 支持离线使用和移动设备

**非目标：**

- 不创建用户账号系统（学习数据存储在浏览器本地）
- 不实现在线协作功能
- 不支持视频流媒体播放
- 不使用需要后端服务的 AI 功能（语音合成使用浏览器内置 API）
- 不修改 AetherViz Master 的核心渲染引擎

## 决策

### 1. 架构模式：模块化组件系统

**决策**：采用模块化组件架构，每个教学主题作为独立模块实现。

**理由**：
- 保持代码可维护性和可扩展性
- 不同主题可以独立开发和测试
- 便于后续添加新的学科和知识点

**架构层次**：

```
┌─────────────────────────────────────────────┐
│         UI Layer (儿童友好界面)              │
│  ┌──────────────┐  ┌──────────────────────┐ │
│  │ 控件组件     │  │ 语音提示组件         │ │
│  │ (大按钮)     │  │ (Web Speech API)     │ │
│  └──────────────┘  └──────────────────────┘ │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│      Game Layer (游戏化学习)                 │
│  ┌──────────────┐  ┌──────────────────────┐ │
│  │ 问答系统     │  │ 成就系统             │ │
│  │ 任务系统     │  │ 进度追踪 (LocalStorage)│ │
│  └──────────────┘  └──────────────────────┘ │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│    Content Layer (教学内容模块)              │
│  ┌──────────────┐  ┌──────────────────────┐ │
│  │ 数学模块     │  │ 科学模块             │ │
│  │ (几何/分数)  │  │ (机械/三态/生物)     │ │
│  └──────────────┘  └──────────────────────┘ │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│    Visualization Layer (AetherViz 核心)      │
│  Three.js 3D 渲染 + SVG Overlay + KaTeX     │
└─────────────────────────────────────────────┘
```

### 2. 语音合成技术选择

**决策**：使用浏览器内置的 Web Speech API (`speechSynthesis`)。

**考虑的替代方案**：
1. **第三方语音服务**（如 Google Cloud TTS、Azure Speech）：
   - ❌ 需要网络连接和 API 密钥
   - ❌ 违反零依赖原则
   - ✅ 语音质量更高

2. **预录制音频文件**：
   - ❌ 增加 HTML 文件大小
   - ❌ 无法动态生成语音内容
   - ✅ 音质可控

3. **Web Speech API**（选择）：
   - ✅ 零依赖，浏览器内置
   - ✅ 支持动态内容合成
   - ✅ 支持中英文
   - ⚠️ 语音质量因浏览器而异
   - ⚠️ 需要处理浏览器兼容性

**实现策略**：
- 提供多种语音选项，用户可选择
- 检测语音支持并优雅降级（不支持的浏览器隐藏语音功能）
- 语音速度默认设置为 0.8（比正常慢 20%）
- 所有语音提示可关闭并保存设置

### 3. 数据持久化方案

**决策**：使用浏览器 LocalStorage 存储学习进度和成就。

**考虑的替代方案**：
1. **IndexedDB**：
   - ✅ 支持大数据量存储
   - ❌ API 复杂，学习曲线陡峭
   - ❌ 对于简单数据结构过于复杂

2. **Cookies**：
   - ✅ 兼容性好
   - ❌ 容量限制（4KB）
   - ❌ 每次 HTTP 请求都会携带

3. **LocalStorage**（选择）：
   - ✅ API 简单易用
   - ✅ 容量足够（5-10MB）
   - ✅ 数据持久化
   - ❌ 仅支持字符串（需 JSON 序列化）

**数据结构设计**：

```javascript
// LocalStorage 键值设计
{
  "aetherviz_progress": {
    "completedTopics": ["geometry-basic", "fraction-intro", ...],
    "currentTopic": "length-measurement",
    "learningTime": 3600,  // 秒
    "streakDays": 5
  },
  "aetherviz_achievements": {
    "badges": ["math-explorer", "science-beginner"],
    "quizStreak": 10,
    "tasksCompleted": 15
  },
  "aetherviz_settings": {
    "voiceEnabled": true,
    "voiceRate": 0.8,
    "mode": "simple",  // simple / full
    "fontSize": 100
  }
}
```

### 4. 3D 模型资源管理

**决策**：使用程序化生成（Procedural Generation）创建所有 3D 模型。

**理由**：
- 零外部依赖，无需下载模型文件
- 文件体积小
- 可以动态调整模型参数

**实现方式**：
- **几何图形**：Three.js 基础几何体（BoxGeometry、SphereGeometry 等）
- **复杂模型**（如杠杆、滑轮）：组合多个基础几何体
- **粒子效果**：THREE.Points + BufferGeometry
- **SVG 图表**：D3.js 动态生成

**示例代码结构**：


## 风险 / 权衡

### 风险 1：浏览器兼容性差异

**描述**：不同浏览器的 Web Speech API 实现和质量差异较大。

**缓解措施**：
- 提供功能检测，不支持的浏览器隐藏语音功能
- 提供文字版本作为替代
- 测试主流浏览器（Chrome、Edge、Safari、Firefox）

---

### 风险 2：移动设备性能限制

**描述**：低端移动设备可能无法流畅运行 3D 场景。

**缓解措施**：
- 提供性能设置选项（降低粒子数量、简化渲染）
- 检测设备性能并自动调整画质
- 提供"轻量模式"切换

---

### 风险 3：LocalStorage 数据丢失

**描述**：用户清除浏览器缓存会导致学习进度丢失。

**缓解措施**：
- 提供数据导出功能（导出为 JSON 文件）
- 提供数据导入恢复功能
- 在界面提示用户定期导出数据

---

### 风险 4：内容开发工作量

**描述**：开发覆盖 1-6 年级的完整题库和教学内容需要大量时间。

**缓解措施**：
- 采用迭代开发策略，优先开发核心主题
- 建立内容模板，简化新主题开发流程
- 邀请教师参与内容审核和创作

---

### 风险 5：小学生注意力分散

**描述**：过多的游戏化元素可能分散学习注意力。

**缓解措施**：
- 保持游戏化元素与学习内容的紧密关联
- 提供"专注模式"关闭游戏化功能
- 教师版本允许禁用成就和排行榜
